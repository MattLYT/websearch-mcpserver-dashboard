WebSearch MCP 控制中心

在原有 websearch-mcpserver 之上增加一个默认关闭、只读的本机控制台：被动记录每一次工具与来源调用，解释失败原因，展示来源健康与熔断状态，并保留请求级调用链。不主动探测、不保存完整查询。

四工具同屏 失败分类 最小样本置信度 只读熔断 请求关联 Prometheus 出口
本次扩展的分支 上游项目（原作者维护） English
本项目是基于 daidaiJ/websearch-mcpserver 的扩展分支，遵循上游的 MIT 许可与社区规范。 控制中心是可选附加模块，默认 dashboard.enabled: false，不改变四个 MCP 工具的参数、返回与调用行为； 上游原始功能、文档与发布流程保持原样，相关成果与著作权归原作者。

系统结构

数据只往一个方向流动：真实调用产生事件，事件驱动控制台，控制台从不反向触发搜索。

MCP 工具层smartsearch · academicsearch · cleanfetch · pdf_parser
→
被动遥测层工具事件 + 来源事件，SQLite 存储，查询哈希而非原文
→
本地控制台总览 · 搜索源 · 调用记录 · 设置（loopback 限定）
→
可选出口只读 Admin API 与 Prometheus 文本指标

控制中心提供什么

失败语义

把失败归类为限流、验证码、访问被拒、超时、网络、解析失败、无结果与未知；来源行直接显示失败构成与 P95 延迟。

告警可信度

基于最近 20 次调用判定健康，样本不足 5 次时标记为“样本不足”，避免把一次波动读成来源损坏。

只读熔断

连续 3 次失败才进入暂停，按错误类型给出不同暂停时长并显示恢复时间；成功即清除。控制台只报告，不改变搜索路径。

请求关联

每次工具调用生成 request id，工具事件与其触发的来源事件共享同一标识，可在页面上展开一次调用的来源链。

四工具固定展示

四个公开 MCP 工具始终可见，未调用过的工具显示为“可调用 · 尚无观测”，不会因为历史为空而消失。

机器可读出口

/__admin/api/providers 给脚本读取来源状态，/__admin/api/metrics 提供 Prometheus 文本指标，供 Grafana 等现有栈消费。

界面

快速开始

保持上游原有的启动方式，只多一个可选的控制中心开关。

Docker Compose

services:
  websearch:
    image: ghcr.io/daidaiJ/websearch-mcpserver:latest
    ports: ["127.0.0.1:8338:8338"]
    environment:
      - TAVILY_SK
      - EXA_API_KEY
      - JINA_API_KEY
    volumes:
      - websearch-data:/data
      - ./config.yaml:/app/config.yaml:rw
volumes:
  websearch-data:

配置文件

dashboard:
  enabled: true
  storage_path: ./data/dashboard.db
  retention_days: 30
  secrets_path: ./data/dashboard-secrets.json
  suspension:
    ban_time_on_fail: 5s
    max_ban_time_on_fail: 24h
    suspended_times:
      rate_limit: 3m
      captcha: 1h
      access_denied: 24h

打开 http://127.0.0.1:8338/dashboard/ 即可看到控制台；它只允许本机访问，与 MCP 端点共用同一个 loopback 边界。

数据与隐私

只保存脱敏元数据

查询以哈希 + 主题 + 语言 + 关键词的形式落库，完整查询与 URL 不写入数据库；密钥只保存在独立的私密覆盖文件，接口与页面都不回显原值。

只做被动观测

控制台不发起任何健康探测，也不会因为某个来源“被暂停”就跳过调用；它只呈现真实发生过的调用结果。
